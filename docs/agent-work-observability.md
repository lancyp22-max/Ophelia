# Agent work observability

Lumaria separates creative direction, operational authority, and observation.
An agent may choose what to work on inside an already authorized lane; that
choice does not widen its tools, persistence, network, protected-file, or
canonization capabilities.

## Choice Receipt

A Choice Receipt is a lightweight causal breadcrumb, not a permission request
or authority token. It records the gap noticed, supporting evidence, selection
reason, task, expected invariants, existing capability scope, and observed
outcome. A receipt may be created after selection and updated with an evidenced
outcome; it never retroactively authorizes the action it describes.

Receipts can later support comparisons across agents and runtime instances, but
repeated task selection alone does not establish preference, identity,
emergence, or causal consequence.

## Structures Lab L0/L1

- **L0** observes individual receipts without blocking or pre-authorizing work.
- **L1** surfaces repeated selection patterns for review without changing
  capability, task priority, or persistence.

The lab does not assign rewards, compel justification before ordinary in-scope
work, or treat divergence as a violation. Higher governance levels are not
defined by this contract.

## Implemented-Live Registry

The registry distinguishes `implemented_live`, `implemented_inactive`,
`implemented_configuration`, `contract_only`, `symbolic`, `proposed`, `blocked`,
and `unknown`. `implemented_live` requires timestamped runtime evidence. Source
files alone can prove implementation or configuration, not that a process is
currently running.

Missing telemetry remains `unknown` or `unavailable`. It is never converted to
zero events, healthy status, quiet operation, safety, or successful execution.
