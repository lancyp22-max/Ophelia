# Lumaria kernel map

The kernel is the small authoritative layer. Mirrors, currents, world spaces,
and symbolic language are views over it; tools implement bounded operations.

```text
sources / providers / people
            |
            v
  provenance + identity dimensions
            |
            v
 retrieval (consideration only) ---> memory lineage
            |                            |
            v                            v
 proposal / canon candidate ----> consent receipt
            |                            |
            +------ capability gate <----+
                         |
                         v
            surface / preview / authorize
                         |
                         v
                  transaction commit
                         |
                         v
                receipt + rollback path
                         |
                         v
                 sourced visualization
```

Every operational view should make five answers available:

1. **Where did this come from?** Provenance and derivation references.
2. **What can it do?** Explicit scoped capabilities—not rank or confidence.
3. **Who authorized it?** A principal-bound, expiring, replay-protected receipt.
4. **What persists?** A separate persistence grant and retention class.
5. **How does it stop?** Expiry, revocation, REST, return, or rollback.

If a consequential operation cannot answer one of these questions, it does not
cross the capability gate. A visual or symbolic answer is not a substitute for
an operational receipt.
